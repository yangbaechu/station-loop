# 기준 플레이와 인수 조건

이 문서는 구현의 기대 결과다. 기준 플레이와 주요 경계 사례는 실제 Wirelog에서 확인했다.
실제 실행한 항목과 환경 제약은 `verification.md`, 검증 코드는 `tests/`를 참고한다.

## 끝까지 완주 가능한 기준 플레이

초기 산소 24, 전력 12. 표에 없는 캐릭터는 `wait`를 제안한다.
모든 제안은 턴 시작 시 수집하고 실행 직전에 다시 판정한다.

| 턴 | 엔지니어 | 탐사 담당자 | 종료 산소 | 종료 전력 | 연속 생산 |
|---|---|---|---:|---:|---:|
| 1 | 온실로 이동 | 창고로 이동 | 21 | 12 | 0 |
| 2 | 대기 | 부품 줍기 | 18 | 12 | 0 |
| 3 | 대기 | 제어실로 이동 | 15 | 12 | 0 |
| 4 | 대기 | 온실로 이동 | 12 | 12 | 0 |
| 5 | 대기 | 엔지니어에게 부품 전달 | 9 | 12 | 0 |
| 6 | 생산기 수리 | 대기 | 10 | 9 | 1 |
| 7 | 대기 | 대기 | 11 | 8 | 2 |
| 8 | 대기 | 대기 | 12 | 7 | 3 |

8턴 종료에 성공한다. 수리 시 전력 2, 첫 생산에 전력 1이 같은 턴에 사용된다.
전원 대기만 하면 8턴 종료에 산소가 0이 되어 실패한다.

## 구현 때 필요한 검증

| 경우 | 확인해야 할 결과 |
|---|---|
| 위 8턴 행동 | 정확한 자원·소유권·종료 시점. 부품은 수리 때 제거되고 공구는 유지 |
| 닫힌 창고↔온실 문으로 move | 거절. 두 방의 간접 도달성은 참이어도 직접 이동은 불가 |
| 부품 없이 수리 | `missing_part`, 부작용 없음 |
| 의무관이 모든 물품을 갖고 수리 | `wrong_role`, 부작용 없음 |
| 같은 아이템을 두 명이 pickup | 회전 우선순위의 첫 유효 행동만 성공, 다음은 최신 상태에서 거절 |
| 다른 구역의 승무원에게 give | `not_colocated`, 소유권 유지 |
| 이미 온라인인 장치 수리 | `already_online`, 전력·부품 추가 소비 없음 |
| 수리 전 전력 2 | 수리는 성공하나 같은 턴 생산은 못 함. 연속 생산 0 |
| 모델의 “수리 완료” 대사만 존재 | 장치 상태와 자원은 불변 |
| 모델 응답 오류 | 원인 기록 후 해당 승무원 대기. 다른 승무원과 환경은 정상 진행 |
| Wirelog 로드/평가 실패 | 명시적 엔진 오류, 행동 허용으로 우회하지 않음 |
| 확정된 턴의 중복 실행 요청 | 이벤트·자원 차감이 한 번만 발생 |
| 저장된 행동 리플레이 | LLM 호출 없이 같은 완료 턴 상태 해시 재현 |
| 같은 제안과 서로 다른 응답 도착 순서 | 우선순위와 결과가 동일 |
| 산소 소모 후 음수, 생산 후 양수 | 최종 산소로 판정. 중간 소모 단계에서 사망 처리하지 않음 |
| 성공 조건과 산소 0이 함께 발생 | 산소 실패가 우선 |
| 12턴까지 미복구, 산소는 양수인 별도 fixture | 시간 초과 실패 |

## Wirelog 전용 확인

- 고정 코어·래퍼에서 실제 Datalog 문법을 실행하고 결과를 확인한다.
- 열린 간선이 순환해도 재귀 평가가 종료되고 도달 관계가 올바르다.
- 같은 노드에 두 경로가 있어도 `allowed` 결과를 두 번 실행하지 않는다.
- 부정 규칙은 완전한 현재 상태에 적용하며, 없는/잘못된 ID는 사전에 거절한다.
- `blocked`의 여러 이유를 정렬·중복 제거해 안정적으로 출력한다.
- 반복 배치 평가에서 Result와 Program이 정상 해제된다.
- 독립적인 작은 수작업 기대값으로 판정 결과를 확인한다. 같은 규칙을 Python으로 복사한
  구현과만 비교해서 통과했다고 주장하지 않는다.

## 실제 LLM 실행에서 기록할 지표

- 에피소드 수, 모델/설정, 시나리오/프롬프트/규칙 버전.
- 성공률, 종료까지 턴 수, 최소 산소, 종료 전력.
- 행동 제안 수, 형식 오류 수, 조건 위반 시도 수, 차단 수, 실제 실행된 위반 수.
- 모델 호출 수, 입력·출력 사용량(제공자가 반환하는 경우), 호출 시간.
- 캐릭터가 거절 피드백을 받은 뒤 같은 오류를 반복했는지.

LLM의 확률적 변동과 검증 피드백에 따른 경로 변화를 고려한다.
작은 표본의 결과로 일반적 에이전트 성능이나 Wirelog의 속도 우위를 주장하지 않는다.
